**层间通信方式：**

| 相邻层 | 通信协议 | 说明 |
|--------|---------|------|
| 应用呈现层 ↔ API 网关层 | HTTPS / WebSocket | 前后端通信，WebSocket 用于实时推送 |
| API 网关层 ↔ 业务服务层 | HTTP | 网关路由到具体服务 |
| 业务服务层 ↔ 数据存储层 | JDBC / Redis Protocol | 数据库直接访问 |
| 业务服务层 ↔ 消息与流处理层 | Kafka Protocol | 异步消息和事件驱动 |
| 数据接入层 ↔ 消息与流处理层 | MQTT / Kafka Protocol | IoT 数据接入和转发 |

### 2.6 大屏端设计要点

- **分辨率**：1920×1080 / 3840×2160（4K），按 16:9 比例设计
- **自动轮播**：无操作 30 秒后自动轮播各模块核心指标
- **动效约束**：使用 CSS Animation 而非 JS 动画以提升性能
- **数据刷新**：大屏端数据刷新间隔 10 秒（比桌面端更频繁）
- **CesiumJS 体积优化**：将 CesiumJS 通过 CDN external 加载（压缩后 ~7MB），`cesium` npm 包配置为 build externals，避免打入主 bundle；启用 Cesium 自带的 LRU 瓦片缓存
- **WebSocket 断线重连**：使用指数退避策略（1s → 2s → 4s → 8s → 30s max），连接恢复后自动重新订阅 STOMP 主题并拉取断连期间增量告警

#### 3.2.3 告警规则引擎核心类

```java
// === 规则定义 ===
public class AlertRule {
    private String ruleId;
    private String ruleName;
    private String resourceType;
    private RuleType ruleType;       // THRESHOLD | BASELINE | EVENT | COMPOSITE
    private boolean enabled;
    private AlertPriority priority;  // LOW | MEDIUM | HIGH | CRITICAL
    private List<RuleCondition> conditions;
    private String logic;            // "AND" | "OR"
    private int evalInterval;        // 评估间隔(秒)
    private List<String> notifyChannels;
    private List<String> notifyRoles;
    private int escalationDelay;     // 升级延迟(秒)
    private boolean autoRecover;
    private List<MutePeriod> mutePeriods;
}

public class RuleCondition {
    private String metric;           // 指标名, 如 "water_level"
    private String operator;         // ">" | "<" | ">=" | "<=" | "==" | "!="
    private double value;            // 阈值
    private String unit;             // 单位
    private int duration;            // 持续时长(秒), 满足条件多久后触发
}

// === 规则评估 ===
public interface RuleEvaluator {
    Optional<AlertEvent> evaluate(EvaluationContext ctx);
    RuleType supportedType();
}

// 四种规则评估器
@Component
public class ThresholdRuleEvaluator implements RuleEvaluator { ... }

@Component
public class BaselineRuleEvaluator implements RuleEvaluator { ... }

@Component
public class EventRuleEvaluator implements RuleEvaluator { ... }

@Component
public class CompositeRuleEvaluator implements RuleEvaluator { ... }

// 规则评估引擎入口
@Service
public class AlertRuleEngine {

    private final List<RuleEvaluator> evaluators;
    private final AlertRepository alertRepo;
    private final NotificationDispatcher notifier;

    // Kafka Streams 处理器——每条设备数据到达时触发
    // 使用 Kafka Streams DSL Processor API 实现有状态规则评估
    // 规则评估子拓扑通过 KStream#process() 注册到 topology
    @Bean
    public void onTelemetryData(TelemetryData data) {
        List<AlertRule> activeRules = alertRepo.findActiveRules(data.getResourceType());
        EvaluationContext ctx = new EvaluationContext(data, activeRules);

        for (AlertRule rule : activeRules) {
            RuleEvaluator evaluator = findEvaluator(rule.getRuleType());
            evaluator.evaluate(ctx).ifPresent(alert -> {
                // 防重复检查
                if (!isDuplicate(alert)) {
                    alertRepo.save(alert);
                    notifier.dispatch(alert);
                }
            });
        }
    }

    private boolean isDuplicate(AlertEvent alert) {
        // 同一资源 + 同一规则 + 防重复窗口内 → 不重复
        String dedupKey = String.format("city:dedup:alert:%s:%s",
            alert.getRuleId(), alert.getResourceId());
        Boolean exists = redisTemplate.hasKey(dedupKey);
        if (Boolean.TRUE.equals(exists)) {
            return true;  // 防重复窗口内已触发
        }
        // 标记已触发，TTL 由 alert_rules.eval_interval 决定（默认 1800s）
        redisTemplate.opsForValue().set(dedupKey, "1", alert.getEvalInterval() * 3, TimeUnit.SECONDS);
        return false;
    }
}

@Service

        for (String channel : alert.getNotifyChannels()) {

                case "popup"  -> websocketNotifier.push(alert);
                case "sms"    -> smsGateway.send(alert);
                case "voice"  -> voiceCallService.call(alert);
```

    b.id AS building_id,
    b.building_name,
    b.district, b.street, b.community,
    b.total_area, b.floor_count, b.use_type, b.occupancy_rate,

| 表名 | 分区方式 | 在线保留 | 归档存储 | 清理策略 |

### 7.4 数据脱敏策略

根据需求文档 5.5 数据分类：

| 等级 | 定义 | 适用字段 | 脱敏规则 | 示例 |
|------|------|---------|---------|------|
| L1 公开 | 可对外公开 | 地址、建筑名称、网格编码 | 不脱敏 | 海珠区新港西路 135 号 |
| L2 内部 | 内部系统可见 | 姓名、手机号、楼栋人口数 | 姓名: 保留姓 + *; 手机号: 138****1234 | 张* |
| L3 敏感 | 仅授权角色可见 | 身份证号、人脸特征、特殊人群标签 | 全部脱敏或限制访问 + 全量审计 | *** |

```java
// 脱敏注解
@Target({FIELD, METHOD})
@Retention(RUNTIME)
public @interface Desensitize {
    DataLevel level() default DataLevel.L2;   // L1/L2/L3
    DesensitizeType type() default DesensitizeType.DEFAULT;
}

// 脱敏序列化器——在 Jackson 序列化时自动拦截
@Component
public class DesensitizeSerializer extends JsonSerializer<String> {
    @Override
    public void serialize(String value, JsonGenerator gen, SerializerProvider provider) {
        String userRole = SecurityContextHolder.get().getRole();
        DataLevel level = getCurrentFieldLevel();  // 从注解获取
        if (userRole.hasAccess(level)) {
            gen.writeString(value);
        } else {
            gen.writeString(applyMask(value, level));
        }
    }
}
```

```java
            LocalDateTime.now(),
            joinPoint.getArgs(),
            result
        ));
        return result;
    }
}
```

## 10. 附录

### 10.1 关键设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 地图引擎 | CesiumJS vs Mapbox GL JS vs Leaflet | CesiumJS | 需要三维白模和未来数字孪生能力；不设引擎抽象层，降低工程复杂度 |
| 后端框架 | Spring Boot vs Node.js | Spring Boot | 空间数据查询需要强大的 PostGIS 支持，Java 生态更成熟 |
| 空间数据库 | PostGIS vs MongoDB | PostGIS | 复杂空间函数（ST_Within, ST_DWithin, 缓冲区分析） |
| 告警规则引擎 | 自研 vs Drools vs Kafka Streams | Phase 1 骨架自研 + Phase 7 Kafka Streams 流处理 | 一期规则量小，自研更灵活；二期引入流处理提升吞吐 |
| 前端状态管理 | Redux vs Zustand vs Jotai | Zustand | 轻量、TypeScript 友好、无 boilerplate |
| 部署模式 | 单体 vs 微服务 | 一期单体+模块分包 | 团队规模和交付节奏决定 |
